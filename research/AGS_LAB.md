# AGS Testing Lab (ags-lab-v0.1)

A browser page for trying Adaptive Guided Summarisation as a learner and inspecting it as a researcher. It is a **development tool for a proposed feature**: no learner data, no pilot use, and no claim about learning.

## Open it
1. Unzip the project over your folder, as usual, and run `npm run dev`. Run `npm install` first if you unzipped into a new folder.
2. Full Climb opens as before. For the Lab, go to **http://localhost:5173/ags.html**. Full Climb is unchanged and has no link to the Lab.

## Settings (top right)
- **Ollama (real model)** or **Mock (no model)**.
- The model name and Ollama address start from your saved Full Climb settings. Change the model to `qwen3.5:27b` if it isn't already, then press **Test**. Changes here are saved for the Lab only and don't alter Full Climb's settings.
- Mode and model are locked during a session, so each session uses one setting from start to finish.

## As a learner
1. **Choose a passage:**

   | Passage | Type |
   | --- | --- |
   | TP-01 *Free Buses* | argumentative |
   | TP-02 *The Last Repair* | narrative |
   | TP-03 *Why Bread Rises* | explanatory |

   Then press **Start as a learner**.
2. **Guided questions.** One question at a time, with the passage beside you. The first question follows the passage type.
   - If you're stuck, the passage highlights where to look: first the area, then the paragraph.
   - At the third attempt, the evidence sentences themselves are marked, and you put the idea in your own words.
   - English, Chinese or a mix is fine. Ctrl+Enter submits.
   - **Go to my summary** ends the questions at any time.
3. **Summary.**
   - The questions and your answers are hidden.
   - Aim for 100–150 words (a guide, not a rule).
   - **Optional: show the topics to cover** is hidden by default, and opening it is recorded.
4. **Feedback and revision.**
   - You get at most 3 feedback points, each with **Show where**. The points come from code and never contain the answer.
   - Draft 1 is kept unchanged and shown above the editor. You revise once, and both drafts are saved.

## As a researcher: Researcher Inspector (top right)
Close the Inspector while answering: it shows the hidden ideas.
- **Session:** the model's name, size and quantisation; all version numbers; map source and review status; rule settings (cross-paragraph rule **off** for AGS); events such as leaving early, opening topic labels and failed calls.
- **Key-idea map:** every idea's statement, elements, relationship, evidence (and whether it was found), and its questions.
- **Progress by idea:** outcome, support level (0 none · 1 focused question · 2 pointer · 3 evidence shown), attempts, and review flags.
- **Turns:** for each answer, open it to see:
  1. the model's verdict after the code checks: elements with your quoted words, relationship, alternative, the story interpretation, the model's own reason, and **any judgement the code downgraded**;
  2. the rules: classification, the rule path, next move, support level;
  3. the call: tokens used against the limit, time, prompt hash, and the raw reply.
- **Summary drafts:** idea coverage with your quoted words, relationships, interpretation, unsupported claims, code downgrades, the feedback shown, any points cut by the limit of 3, and the raw reply.
- **Downloads:** this session (JSON), all sessions (JSON), and all turns (CSV). The log lives in this browser (`ags:lab:log:v1`): download it before clearing browser data.

## Marked clearly
- **Mock mode:** a banner says answers are judged by word matching, not a model. Mock records say "MOCK" in the reason.
- **Unreviewed maps:** a banner on every screen says "UNREVIEWED DEVELOPMENT MAP… not for research or learner pilots". It names whether the map is the hand-written test fixture or generated by the model.

## Building a map with the model (development)
**Build a new map with the model** sends the map prompt (`agsmap-v0.2`) for the chosen passage. The result goes through the code checks (`normaliseMap`, `validateMap`) and is shown with its problems and any code changes. **Use this map** is enabled only if the map passes. It stays unreviewed. On a 27B model this can take a few minutes.

## When a call fails
If Qwen's reply is cut off at the output limit, isn't valid JSON, or Ollama can't be reached:
- a red box shows the reason and the token counts;
- **nothing is recorded as an answer**, and your text stays in the box so you can submit again;
- the failed call is logged, with its partial output, under the session's events.
